# 모바일 Safari 가시영역 검증 · 2026-11-16

실물 iPhone Safari에서 `fa0e8ad` 기반 `artifacts/phone-current/index.html`로 가로 시작·이동·일시정지는 동작했다. 주소창이 보이는 상태에서 플레이 화면 하단이 조금 가려졌다는 보고가 있었다. 이 사본에는 전체 화면 버튼이 없었다.

기존 코드는 `innerWidth/innerHeight`를 캔버스와 입력 좌표에 썼고 고정 위치 HUD와 조작부는 브라우저의 배치 영역에 붙었다. Ego에서 배치 영역을 667×375로 유지한 채 가시 높이만 291px로 바꾸자, 기존 사본의 캔버스는 높이 375px, 음소거·일시정지 버튼은 y=316–362, 파동 버튼은 y=285–331에 남았다. 새 코드에서는 캔버스와 카메라·렌더 타깃이 667×291, 음소거·일시정지는 y=232–278, 파동 버튼은 같은 가시 영역 안으로 들어온다. 문서 스크롤은 필요하지 않다.

- 가시 크기와 위치는 `VisualViewport`에서 읽고, 미지원 환경에서는 창 크기로 대체한다. 화면 크기·가시 영역·회전 변경을 프레임 단위로 합쳐 캔버스, 고정 HUD, 팝업 및 조작 좌표에 적용한다.
- 노치와 홈 인디케이터는 브라우저의 safe-area 값으로 피한다. 가로 공간이 낮으면 시작 메뉴의 버튼을 세로 흐름에 두고, HUD와 최대 5개 조작 버튼을 겹치지 않게 줄을 배치한다. 모달 자체 스크롤은 유지한다.
- 지원 브라우저에서는 시작 화면과 일시정지 메뉴에서 전체 화면을 켜고 끈다. 문서에 API가 허용되어 있고 요청·해제 함수가 모두 있는 경우에만 나온다. 브라우저에서 전환을 거부하면 해당 메뉴에 안내를 띄운다.

로컬 서버와 Ego 공간을 열고 다음을 실행한다. `output`에 절대 경로를 지정하면 캡처도 남는다. RED 측정은 옵션에 `baseline="artifacts/phone-current/index.html"`을 추가하고 **fa0e8ad 사본을 제공하는 서버**로 실행한다. 해당 경로는 후속 실물 검수에서 교체될 수 있으므로 새 사본으로 기존 증상을 판단하지 않는다.

```sh
{ printf 'const spaceId=123, tab="p1", base="http://localhost:3044/";\n'; cat scripts/verify-mobile-viewport.ego.mjs; } | ego-browser nodejs
```

가시 높이 291px·274px, 가로 복귀 375px, 가시 원점 이동, 안전 여백 주입, 실제 버튼 탭과 조이스틱, 카탈로그 모달, 새 게임의 전체 화면 진입·해제와 거부·미지원 경로를 확인한다. Ego의 모바일 화면과 주입한 여백은 Safari의 실제 주소창·노치·홈 인디케이터를 재현하지 않는다. 새 빌드의 실물 검수에서는 Safari 주소창이 표시된 가로 상태로 시작해 메뉴와 플레이 조작부의 네 가장자리, 가로↔세로 전환, 화면 스크롤 없이 일시정지·재개를 확인한다.

Safari의 브라우저 툴바는 별개다. 전체 화면 기능이 없는 iPhone에서는 Safari의 공유 메뉴에서 **홈 화면에 추가 → 웹 앱으로 열기**를 선택할 수 있다. 일반 Safari에서도 플레이할 수 있도록 했으므로 설치는 필요하지 않다.
